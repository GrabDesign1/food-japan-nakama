# NAKAMA 課金システム要件定義

## 1. 実装目標

「売りたい」「探している」の掲載完了直前または公開後に、有料オプションを選択・購入できる仕組みを追加する。加えて、売り手が「探している」案件へ新規営業連絡を開始するときに、初回紹介料を課金する。

基本掲載は無料。有料オプションを買わなくても公開申請・掲載・応募・商談ができること。有料オプションの購入は審査通過や成約を保証しない。

基本となる利用ルール：

| 行為 | 料金 |
|---|---:|
| 売りたい案件・探している案件を掲載する | 無料 |
| 公開案件を検索・閲覧する | 無料 |
| 買い手が「売りたい」案件へ問い合わせる | 無料 |
| 売り手が受け取った問い合わせへ返信する | 無料 |
| 売り手が「探している」案件へ初めて営業連絡する | 有料 |
| 同じ売り手・同じ相手・同じ案件内で継続して連絡する | 初回決済後は無料 |

### 1.1 初回紹介料（中心商品）

売り手が、自社の商品・原料・技術を提案するため「探している」案件の掲載者へ新規に連絡を開始する際、初回紹介料を支払う。

初期価格案：

| 商品 | 価格（税込） | 内容 |
|---|---:|---|
| 初回登録特典 | 無料 | 紹介クレジット3件。法人・事業者確認後に付与 |
| 通常案件・1件紹介 | 1,100円 | 1案件・1相手への初回連絡 |
| 5件パック | 4,400円 | 紹介クレジット5件。有効期限180日 |
| 10件パック | 7,700円 | 紹介クレジット10件。有効期限180日 |
| NAKAMA確認済み優良案件 | 3,300円 | 購入条件・時期等を事務局確認済みの案件への初回連絡 |

価格は検証案であり、管理画面の商品マスターで変更可能にする。パック購入は残高クレジットとして管理する。

課金単位は、`売り手組織 × 探している案件 × 掲載者組織` の初回接触1回とする。同一案件・同一相手に対し、担当者や文章を変えて重複課金しない。一度解放した会話は、その案件内に限り継続メッセージ無料とする。

課金しないケース：

- 買い手側から先に問い合わせを受け、そのスレッドへ返信する
- NAKAMA事務局から正式に招待された案件へ、無料招待枠で返信する
- 自社・同一組織への連絡
- 管理者によるテスト・補償クレジット

購入前に、相手企業名、募集概要、募集期限、最終ログインの大まかな状態、本人・法人確認状態を閲覧できるようにする。ただし非公開に設定された情報は開示しない。

紹介料は「メッセージ送信と連絡経路の解放」に対する料金であり、返信・商談・契約・売上を保証しない。ただし次の場合はクレジットを消費せず、決済済みなら自動返還または返金対象とする。

- 案件が送信前に終了・停止・削除されていた
- 相手アカウントが利用停止中で、メッセージを配信できない
- システム障害でメッセージが保存・配信されなかった
- 同一キーに対する二重課金
- 送信後14日を経過しても相手がメッセージを一度も開いていない

相手がメッセージを開いた後に返信しなかった場合は、原則として返還・返金理由にしない。この条件を購入前に明示する。未読判定はサイト内メッセージの開封記録に基づき、メールの開封追跡には依存しない。

### 1.2 NAKAMA確認済み優良案件

1件3,300円を適用するには、管理者が次を確認し、確認日と根拠を記録する。

- 募集者の法人・事業者確認
- 探している商品・原料・技術
- 希望数量または取引規模
- 希望価格帯または予算の有無
- 納品・実施地域
- 必要時期と募集期限
- 継続購入の可能性
- 提案を確認する意思

売り手には購入判断に必要な範囲で、確認済み項目、確認日、募集期限、提案数、最終利用状況を表示する。確認から一定期間が経過した案件は確認済み表示を自動停止し、管理者の再確認を必要とする。

### 1.3 初回無料3件の不正取得対策

- 確認済み事業者・組織単位で一度だけ付与
- 同一法人番号、同一組織、同一決済顧客等への重複付与を防ぐ
- メールアドレスを変えた再登録だけで再付与しない
- 無料クレジットは換金・譲渡不可
- 不正利用時は付与取消・利用停止できる
- 管理者の手動付与・取消は監査ログへ記録する

| 広告枠 | 初期価格（税込） | 販売方法 |

| 記事・特集内バナー | 33,000円～／月 | 同上 |

| バナー制作 | 33,000円～／点 | 掲載費と別料金 |

在庫・掲載面・審査・日程調整が必要なため、Phase 1では即時購入ではなく「申込→管理者見積・承認→決済リンク→掲載」の流れにする。

## 3. 掲載時の利用体験

### 3.1 表示タイミング

案件入力後、公開申請の直前に次を表示する。

> 基本掲載は無料です。より早く、より多くの相手へ届けたい場合は、有料オプションを追加できます。

ボタン：

- `無料で公開申請する`
- `有料オプションを追加する`

無料ボタンを視覚的に隠したり、購入を必須に見せたりしない。

### 3.2 オプション選択画面

4分類で表示する。

1. 目立たせる
2. 条件に合う相手へ届ける
3. 情報を限定する
4. NAKAMA事務局へ依頼する

各カードには価格、税込・税別、期間、開始条件、審査の有無、成果保証がない旨を表示する。

### 3.3 購入確認

- 対象案件
- 商品名
- 適用期間または提供単位
- 金額、消費税、合計
- 掲載開始条件
- キャンセル・返金条件
- 利用規約・広告掲載基準への同意

を表示し、Stripe Checkoutへ遷移する。

### 3.4 決済後

決済成功画面で「決済完了」と「掲載反映」を区別する。

- 自動反映商品：Webhook受信後に有効化
- 審査商品：支払済・審査待ち
- 個別契約商品：相談受付済。即時課金しない

## 4. 掲載順位

無料の自然表示と、有料スポンサー枠を分ける。有料枠には必ず `広告` または `スポンサー` を表示する。

Phase 1は固定期間・固定枠で実装する。スポンサー枠内の基本順位は以下。

1. 掲載状態が有効
2. 検索・カテゴリとの関連性
3. 掲載情報の品質
4. 同条件の場合はローテーション

料金だけで自然検索順位を改変しない。

Phase 3でCPC入札を追加する。最低クリック単価、日額・総額予算、対象キーワード・地域・カテゴリ、表示・クリック計測、無効クリック除外を実装するまで「入札制」と表示しない。

## 5. 管理画面

管理者は次を操作できること。

- 商品マスターの価格、公開状態、期間、適用対象、税区分
- 注文・支払・返金・失敗の確認
- 有料掲載の開始、停止、期間変更
- 審査承認・否認と理由
- バナー在庫、掲載面、期間、リンク、画像、表示状態
- SNS・通知・個別支援の対応状況
- 表示回数、クリック数、CTR
- CSV出力
- 操作履歴

管理者が価格を変更しても過去注文の金額は変えない。注文時の商品名・価格・税・内容をスナップショット保存する。

## 6. 通知

最低限、次のメールまたはサイト内通知を送る。

- 注文受付
- 決済完了
- 決済失敗
- 審査承認／否認
- 掲載開始
- 終了3日前
- 掲載終了
- 返金完了

メールの送信失敗で決済・掲載処理を巻き戻さない。再送可能にする。

## 7. キャンセル・返金

公開文言は法務確認前の仮案とし、管理者が変更可能にする。

- 決済前：キャンセル可能
- 自動掲載開始前：原則キャンセル申請可能
- 掲載開始後：原則返金なし。ただしNAKAMA側の事情で提供できない場合は全額または未提供分を返金
- 審査否認：全額返金または決済前審査
- 二重課金：確認後返金
- SNS・制作・個別支援：着手状況と個別契約に従う

Stripe Dashboardだけで返金した場合もWebhookで注文状態を同期する。

## 8. 審査・禁止事項

- 食品表示、健康・効能、酒類、景品表示、比較・優良誤認等に抵触するおそれのある表現
- 虚偽、権利侵害、違法品、危険品、反社会的内容
- 掲載内容と無関係な誘導
- 個人情報の不適切な公開

広告購入は掲載承認を保証しない。否認理由と返金状態を記録する。

## 9. 実装フェーズ

### Phase 1：固定掲載オプション

- 商品マスター
- 掲載時オプション選択
- Stripe Checkout一回払い
- Webhookによる注文確定
- 注目・PR・急募の自動反映と期限終了
- 注文履歴・管理画面
- 広告表記

### Phase 2：通知・バナー・運用支援

- 条件一致通知
- バナー申込・在庫・審査・掲載
- SNS紹介・個別支援の申込管理
- レポート

### Phase 3：CPC入札広告

- キャンペーン、入札単価、予算
- ターゲティング
- 表示・クリック台帳
- 無効クリック判定
- 残高または事前決済
- 広告主レポート

## 10. 非対象

- 会員間取引代金の代理受領
- エスクロー
- 通常取引への一律成約手数料
- 自動的な成功報酬計算
- 初期リリースでのCPC入札
- 売上・問い合わせ・成約の保証

## 11. 初回連絡の利用体験

1. 売り手が「探している」案件を閲覧
2. `この募集へ提案する` を押す
3. 未ログインならログイン、売り手プロフィール未登録なら登録を案内
4. 初回紹介料、無料条件、返金条件を表示
5. 利用可能クレジットがあれば1件使用、なければ1件購入またはパック購入
6. 提案文を入力し、最終確認
7. サーバー側で案件状態と重複解放を再確認
8. 決済確定またはクレジット確保後にメッセージ送信
9. 以後、その案件・相手とのスレッドは無料
10. 送信後14日間未読の場合、定期処理でクレジットを1件返還

決済とメッセージ送信の間で障害が起きても損失が出ないよう、クレジットは一度 `reserved` にし、送信成功時に `consumed`、失敗時に `released` とする。

### クラウドワークス型として採用する点

- 募集情報の掲載・閲覧は無料
- 案件を探し、応募・提案する市場をつくる
- 有料オプションで露出を増やす
- プラットフォーム内メッセージで履歴を残す
- 確認済み事業者、募集期限、条件を表示する

### 初期段階では採用しない点

- 売買代金の代理受領・エスクロー
- 契約金額からのシステム利用料控除
- 仮払い・検収・報酬支払い
- 全取引への成約手数料

まずは「募集・閲覧は無料、売り手からの新規提案は有料」というリード課金型にする。
